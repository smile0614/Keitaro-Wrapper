# Обёртка над Keitaro

Веб-приложение на FastAPI + SQLAlchemy для работы с рекламным трекером Keitaro через Admin API.

Что умеет:

1. **Создаватор кампаний.** Принимает название, гео (одну или несколько стран) и оффер. Создаёт в Keitaro кампанию с доменом, группой и источником и двумя потоками:
   - первый ловит всех из указанных стран и редиректит на Google;
   - второй отправляет остальных на выбранный оффер.
2. **Редактор кампании.** Подтягивает потоки из Keitaro, умеет добавлять и удалять офферы, пинить веса, публиковать изменения и отменять их.

## Стек

- Python 3.11+
- FastAPI, SQLAlchemy 2, Alembic
- httpx для запросов к Keitaro API
- SQLite по умолчанию, любая другая база через `DATABASE_URL`
- Фронтенд: HTML и чистый JavaScript, отдаётся самим FastAPI

## Запуск

1. Создать виртуальное окружение и поставить зависимости:

   ```bash
   python -m venv .venv
   ```

   Windows:

   ```bash
   .venv\Scripts\activate
   ```

   Linux / macOS:

   ```bash
   source .venv/bin/activate
   ```

   ```bash
   pip install -r requirements.txt
   ```

2. Скопировать `.env.example` в `.env` и заполнить:

   | Переменная | Описание |
   |---|---|
   | `KEITARO_URL` | адрес Keitaro, например `https://tlgk.host` |
   | `KEITARO_API_KEY` | API-ключ из админки Keitaro |
   | `CAMPAIGN_PREFIX` | префикс названий кампаний, например `test_ivanov_` |
   | `DATABASE_URL` | строка подключения SQLAlchemy, по умолчанию `sqlite:///./keitaro_wrapper.db` |
   | `KEITARO_TIMEZONE` | необязательно, часовой пояс для статистики, по умолчанию `Europe/Moscow` |

3. Применить миграции:

   ```bash
   alembic upgrade head
   ```

4. Запустить сервер:

   ```bash
   uvicorn app.main:app --reload
   ```

5. Открыть http://127.0.0.1:8000. Документация API (Swagger) доступна на http://127.0.0.1:8000/docs.

## Миграции

Миграции лежат в `alembic/versions`. Alembic берёт адрес базы из `DATABASE_URL`.

```bash
alembic upgrade head
```

```bash
alembic downgrade -1
```

После изменения моделей в `app/models.py` новая миграция создаётся так:

```bash
alembic revision --autogenerate -m "describe change"
```

Чтобы работать с PostgreSQL, достаточно поставить драйвер (`pip install psycopg[binary]`) и указать, например, `DATABASE_URL=postgresql+psycopg://user:password@localhost:5432/keitaro_wrapper`.

## Тесты

```bash
pytest
```

Тесты проверяют расчёт весов и логику редактора (добавление, удаление, отмена, публикация, пины, синхронизация с Keitaro) на фейковом клиенте Keitaro и SQLite в памяти, без сетевых запросов.

## Как пользоваться

### Создание кампании

На главной странице:

1. Ввести название (префикс из `CAMPAIGN_PREFIX` подставится сам).
2. Ввести гео через запятую, например `MX, AU, RO`.
3. Выбрать оффер в поиске: можно искать по названию или по ID.
4. Выбрать домен, группу и источник. По умолчанию выбраны группа и источник `FORTESTS`.

Алиас кампании генерируется из названия со случайным суффиксом, например `test-akio-campaign1-84fbeb`.

Если создание потоков не удалось, кампания удаляется из Keitaro, чтобы не оставлять полусозданных кампаний. Keitaro не даёт повторно использовать название кампании, которая лежит в архиве, поэтому после такой ошибки нужно выбрать другое название.

Там же можно открыть существующую кампанию по её ID в Keitaro.

### Редактор потоков

- **Fetch streams from Keitaro** загружает потоки кампании. Потоки без офферов показываются просто как потоки, их содержимое обёртка не разбирает.
- **Add** добавляет оффер в поток. Веса пересчитываются поровну, поток становится жёлтым: изменения ещё не опубликованы.
- **Remove** помечает оффер удалённым. Он становится серым с долей 0%.
- **Bring back** возвращает удалённый оффер.
- **Publish** отправляет текущий набор офферов и весов в Keitaro.
- **Cancel** отменяет неопубликованные изменения: добавленные офферы удаляются из базы обёртки, удалённые и изменённые возвращаются к опубликованному состоянию.
- **Пин веса.** Иконка 📌 закрепляет текущую долю оффера. Пин сохраняется сразу и не требует публикации: в Keitaro понятия пина нет, а сами доли от него не меняются. Закреплённая доля учитывается при следующих добавлениях и удалениях офферов: она остаётся прежней, остаток делится поровну между незакреплёнными офферами.
- Клик по проценту позволяет ввести долю вручную. Она закрепляется, остальные доли пересчитываются, и такое изменение нужно опубликовать через **Push to KT**.
- Если оффер удалили прямо в Keitaro, то после **Fetch** он не пропадает, а попадает в удалённые, и его можно вернуть через **Bring back**.
- **Show all offers** открывает список всех офферов, доступных в Keitaro, с фильтром и пометкой, в каком потоке этой кампании оффер используется.
- **Stats** — клики, конверсии и доход оффера в этом потоке за последние 7 дней, **Trends** — график кликов по дням за те же 7 дней. В заголовке потока показаны клики за сегодня. Данные берутся из отчётов Keitaro (`/report/build`).
- Ссылка **(preview)** открывает превью оффера в Keitaro, если оно есть.

## Как считаются веса

1. Удалённые офферы получают 0%.
2. Закреплённые офферы сохраняют свою долю. Если сумма закреплённых больше 100%, операция отклоняется.
3. Остаток `100 - сумма закреплённых` делится поровну между незакреплёнными активными офферами. Остаток от деления раздаётся по 1% первым офферам, поэтому три оффера получают 34/33/33, как в самом Keitaro.
4. Опубликовать поток можно только если сумма долей активных офферов равна 100%.

## Как устроено хранение

Для каждого оффера в потоке хранятся два состояния:

- текущее (`state`, `share`) — то, что видно в интерфейсе;
- опубликованное (`published_state`, `published_share`) — то, что сейчас в Keitaro.

Поток считается неопубликованным, если у какого-то оффера эти состояния различаются. Отмена возвращает текущее состояние к опубликованному, публикация делает наоборот. Флаг пина хранится только в обёртке, в Keitaro такого понятия нет.

## Структура проекта

```
app/
  main.py       маршруты FastAPI
  services.py   логика создания кампаний и редактора
  weights.py    расчёт долей
  keitaro.py    клиент Keitaro Admin API
  offers.py     поиск офферов с кэшем
  stats.py      статистика и тренды из отчётов Keitaro
  models.py     модели SQLAlchemy
  schemas.py    схемы ответов API
  config.py     настройки из .env
  db.py         подключение к базе
alembic/        миграции
static/         фронтенд
tests/          тесты
```

## Ограничения

- API-ключ тестового аккаунта видит не все офферы. В поиск можно ввести ID оффера напрямую: если ключу не хватает прав прочитать его название, оффер покажется как `Offer #ID`.
- Статистика загружается отдельным запросом после открытия страницы, поэтому цифры появляются через секунду-две. Если отчёт недоступен, страница работает без статистики.
